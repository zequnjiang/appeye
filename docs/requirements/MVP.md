## 1. 产品目标

Appeye 帮助信贷行业研究人员持续观察不同国家 Google Play 和 App Store 中应用的变化。在一个后台完成发现应用、人工判断是否属于信贷、持续采集、比较历史、阅读评论和追踪采集任务。

首版面向单团队、单管理员、单主机部署。使用 Node.js 24+、TypeScript、Express、React/Vite 和 Node 内置 `node:sqlite`。Google Play 使用 `google-play-scraper`，App Store 使用 `app-store-scraper`。数据以 SQLite 的关系字段和原始 JSON 并存，方便 AI 或人工通过 SQL 查询、审计和二次分析。

首版不承诺全市场覆盖、精确新增下载量、商店实时数据、应用贷款牌照核验、法律合规结论、付费订阅或多租户服务。

## 3. 核心用户流程

1. 管理员登录，查看各国已跟踪应用、待判断候选、首次发现、近期变化和采集健康状态。
2. 为一个国家配置检索关键词，运行发现任务；或者手动输入商店应用标识添加应用。
3. 应用先进入候选列表，管理员将其标记为 `confirmed`（确认信贷）、`candidate`（待判断）或 `excluded`（排除）。
4. 系统按配置周期采集受跟踪应用，也可以手动触发采集。管理员查看排队、执行、成功、失败和重试状态。
5. 打开应用详情，查看当前基本信息、首次发现时间、商店发布日期、版本历史、字段变化、评分/评论量等趋势及评论样本。
6. 在应用库按国家、商店、分类或文本搜索，比较市场变化，并通过 GitHub 追踪后续需求与缺陷。

## 4. 数据口径（必须遵守）

### 4.1 身份与发现

- 跟踪对象以 `(country, store, storeAppId)` 唯一标识，同一应用在不同国家为不同跟踪对象。
- 实现中商店应用标识的 API / TypeScript 字段命名为 `externalId`，对应需求中的 `storeAppId`；不应与数据库内部的应用记录 ID 混淆。
- Google Play 使用包名；App Store 使用商店数值 ID，并在可用时保留 bundleId。
- `firstSeenAt` 是本系统首次观测时间，绝不能写成实际新上架时间。
- `releasedAt` 是商店返回的发布日期，可为空；`storeUpdatedAt` 是商店披露的更新时间，可为空。
- 首页“新发现”只表示本系统新发现。只有存在可信商店发布日期时，才可另外呈现“商店发布”。
- 关键词命中不能自动变成“确认信贷”，也不能推出具备当地贷款经营许可。

### 4.2 当前信息和历史

- 尽量保存名称、图标、开发者、商店链接、分类、描述、版本、评分、评分/评论数量、价格/币种、发布时间和更新时间；商店未提供的字段为 `null` 或显示“未提供”。
- 每次成功采集保存观测时间、规范化数据和原始响应 JSON，采集失败不覆盖最后成功数据。
- 对连续成功观测比较版本、描述、评分、评分/评论数量、安装区间等可用字段，并持久化变化记录。首次快照不伪造“发生更新”。
- 趋势图使用实际观测时间，不能生成看似真实的历史数据。
- 版本变化次数及频率仅根据系统已观测版本推算，标注观测窗口。不能将评分变化或采集次数算作版本更新。

### 4.3 下载和安装

- Google Play 安装量或安装区间是商店公开的累计安装指标，通常不具有所选国家的独立归属。后台必须显示其累计口径及非国别局限。
- 不能把两个累计安装观测之差直接标成“该国当日下载量”。
- App Store 不公开的下载量为 `null`，显示“未提供”；不得以零、评分数量或估算值替代。
- 首页的国家维度统计可以计数跟踪应用、变化和任务，不得对应用安装量求和后命名为“国家市场下载量”。

### 4.4 评论

- 保存稳定评论 ID、所属跟踪应用、评论时间、评分、文本、可用的标题/版本、采集国家、语言及观测时间。
- 重复采集同一条评论不会增加重复行；可按商店稳定评论 ID 与跟踪应用做唯一约束。缺失 ID 时使用稳定内容标识，并记录该情况。
- 评论是有限页数/条数、所选排序和商店接口返回的样本，界面标注“评论样本”及采集范围，不能称为全量用户评价。
- Google Play 的 `country` / `lang` 请求参数不构成评论作者所在国家的证据；展示的是采集上下文。

### 4.5 演示数据

- 演示模式有持续可见的提示，数据使用独立数据库或同等强度的隔离机制。
- 不能在真实采集失败时静默回退为演示数据，不能把演示变化显示为真实市场动态。
- 演示启动、真实启动与数据存储位置应在 README 中清楚说明。

## 6. 任务与运行行为

- 首版串行或有限并发即可，默认采用保守采集节奏；不得无界并发请求商店。
- 周期、失败重试次数与退避策略应明确并可从配置或环境变量了解。
- 单个国家、关键词或应用失败不会阻断其他任务。失败记录包含足够定位的错误信息，不泄露凭据。
- 重试是有限的；最终失败可从后台查看，并可再次发起任务。
- 暂停国家后不再自动为其新增周期任务；已入队任务是否继续执行需明确且保持一致。
- 商店采集可能受网络、限流、接口结构或地区可见性影响，后台展示实际结果与失败，不保证全覆盖或实时性。

## 7. 数据模型最小约定

允许开发工程师调整命名和表拆分，但需保留以下语义：

| 实体 | 最小语义 |
| --- | --- |
| countries | 国家代码、名称、语言、启用状态、采集间隔与关键词配置。 |
| apps | 国家、商店、商店应用标识、人工分类、首次发现、最后成功观测和当前基本字段。 |
| snapshots | 所属应用、观测时间、规范数据、原始 JSON；可追溯全部历史观测。 |
| changes | 所属应用、字段、旧值、新值、观测时间及来源快照。 |
| reviews | 稳定唯一标识、所属应用、评论字段、请求国家/语言和观测时间。 |
| jobs | 任务类型、国家/应用/关键词参数、状态、尝试次数、计划执行时间、错误及时间戳。 |

数据库启用外键约束和适合单主机运行的事务策略。文档说明安全备份方式；机器可读 JSON 中的时间使用统一格式。用户不需要安装额外数据库服务。
