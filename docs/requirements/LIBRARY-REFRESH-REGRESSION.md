## 反馈、选择与证据边界

用户在 #21 交付后反馈“页面中的 App 列表清单被刷新”，影响使用；反馈截图的已知上下文为 817×863、泰国应用库、页面顶部。用户本轮进一步明确选择：**保持当前清单，有新数据时提示，点击后更新。** 此选择覆盖原 SR-AC-01/04 中自动应用后台新结果的行为，原需求及验收报告保留其历史口径。

CTO 已用合成浏览器红用例复现一个明确缺陷：817×863、原 `scrollY=0`，列表首部插入一行后，阅读恢复将页面滚到 90，标题顶部从 163 变成 73。其原因是顶部控件区域错误使用首个应用行作为阅读锚点。该证据不等于已经在正式页面证明用户反馈只有这一种原因；正式页面观察需记录实际行为，区分清单内容替换、滚动、闪空或重新导航。

原 #21 的交互回归使用真实浏览器计时但拦截 API 的合成数据，正式部署另核验产物和 API。本次必须增加实际认证页面、实际 API 的浏览器证据，不以原通过结论或仅合成测试替代。

## 本轮行为

应用库保留每 15 秒后台检测。同一查询分别保存“当前显示清单”与“待应用结果”：后台成功返回的新结果只更新待应用状态，不能自动改变表格行、顺序、行内内容、总数或分页信息。检测到当前清单确有变化时，显示可操作的更新提示；不能把成功轮询本身当成新数据。

用户点击提示后，一次性应用该查询最新成功的待更新结果，行、总数和分页保持同一快照。显式刷新也表示用户主动更新：可重新请求并应用成功结果；失败保留当前清单和已有待更新资料。首次进入且该查询没有显示缓存时正常加载，用户主动切换国家、商店、分类、搜索或页码可以加载对应查询，不受旧查询的待更新结果干扰。

进入详情再返回时优先恢复原查询的显示清单、输入/筛选、页码、阅读位置和待更新提示，不能因为返回或重新可见就自动应用后台结果。缓存仍为会话内有界缓存；无缓存的默认行为、身份隔离与过期请求保护延续 #21。

后台检测本身不能引起阅读恢复或滚动。主动应用更新或详情返回时，顶部/控件区域维持原视口；正文阅读区域尽量保持原应用 ID 的相对位置。应用消失、结果为空或页码失效时采用明确的有效回退，不循环请求或跳入无效页。

## 验收标准

| 编号 | 要求与必要验证 |
| --- | --- |
| LRR-AC-01 | **显示与检测分离。** 至少连续两个实际 15 秒检测周期中，未点击更新时当前行的身份、顺序、显示内容、总数与分页保持原快照，不闪空、不重新导航、不自动滚动或抢焦点。后台有变化只形成提示；同结果不制造提示或无意义的视口恢复。 |
| LRR-AC-02 | **用户明确应用。** 点击待更新提示后自动采用当前查询最新成功的待应用结果，行/总数/分页原子一致；显式刷新可拉取并应用成功结果。多个后台结果不能使旧结果随后覆盖新结果；待更新提示应与是否仍有未应用差异一致。不得靠永久停止检测或让更新按钮无效维持稳定。 |
| LRR-AC-03 | **查询、返回与会话隔离。** 国家/商店/分类/搜索/页码的显示与待更新状态按完整查询分别保存；切条件原子重置适用页码。详情返回立即恢复原显示清单及待更新提示，保留输入、筛选、页码、阅读位置与合理焦点。快速切换、迟到响应、退出/重登不得串用旧查询或旧会话数据；缓存淘汰后的首次加载明确且有界。 |
| LRR-AC-04 | **顶部与正文位置。** 在 817×863 顶部连续检测新行及无变化结果时维持顶部/控件位置；手动应用和详情返回也不把顶部用户推入表格。正文阅读保留可用的应用 ID 相对位置；锚点删除、结果变空及末页失效采用可验证的有效回退。提示出现不能自行把列表推走，轮询不得扰动搜索输入或正在操作的控件。 |
| LRR-AC-05 | **失败与生命周期。** 首次无缓存加载、成功空结果、已有清单后台失败分别处理。失败保留显示结果及可用待更新资料，轻量错误提示不得冒充更新成功或清空表格；恢复后继续检测。隐藏标签暂停新周期请求，重新可见只补一次且仍须点击才应用；单次有效请求、取消与卸载清理延续 #21。 |
| LRR-AC-06 | **实际页面与独立交接。** CTO 自检后由 Alex 独立验证上述行为；正式认证服务、实际 API、817×863 泰国应用库的顶部连续轮询、滚动阅读、详情返回及主动更新需有时间、截图/可复查记录与请求证据，至少两个真实周期。必须记录实际变化是否发生；若未遇到真实新结果，不把合成的更新提示/应用测试写成生产实测，需补足这一实际链路后再给该链路通过。合成数据只补新行、删除、末页、慢响应、错误等确定性边界，不能往正式库插入假数据取证。报告注明源码/构建/正式加载产物对应、实际与合成范围、必要类型/构建及针对性回归结果；PM 最终逐项验收后才可关闭 #25。 |
