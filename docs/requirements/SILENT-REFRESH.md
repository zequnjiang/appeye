## 问题与预期行为

应用库当前每15秒触发读取，加载时将整张表替换；打开详情又卸载列表，本地搜索、筛选、页码和阅读位置因此丢失。用户已选择**自动静默更新**：保留自动获取并应用新数据，不改成仅提示用户点击刷新。

首次进入且当前查询没有缓存时显示加载态。后续刷新保留现有列表与可操作内容，响应成功后自动应用；失败保留旧数据，提供轻量失败提示并允许随后恢复。合法空结果与加载、失败状态分开。

列表查询条件及阅读上下文提升到同一登录会话内的页面状态。缓存最多20个完整查询，采用有界淘汰；查询键包含国家、商店、分类、搜索、排序、页码/分页大小等实际影响结果的参数。缓存不跨登录身份或真实/演示上下文，退出或身份切换清理。

详情返回时立即读取原查询缓存，恢复筛选、搜索、分页与阅读锚点，然后后台更新。以可见应用ID和行相对视口位置恢复阅读，不仅记录绝对scrollTop；自动加入、排序或高度变化不应把正在阅读的记录推离原位置。返回可恢复原入口焦点，轮询不得抢走正在编辑/操作控件的焦点。

切换查询条件时一次性更新条件及页码0，不能短暂请求“新条件+旧页码”。不同查询的缓存互不串用；旧请求晚到不得覆盖当前查询。标签页隐藏暂停周期请求，重新可见补一次；同一列表仅保留一个有效刷新请求，避免定时器和返回/切换事件叠加。

边界：锚点被删除或不再匹配时，优先使用原位置附近仍存在的记录，全部失效才回到有效列表起点；末页因数据减少失效时落到有效页，不无限重试。直接进入详情或缓存已被淘汰而没有列表上下文时，返回正常默认列表，首次加载可以显示加载态。此缺陷不改服务器采集周期、分类口径或原批次数据。

## 验收标准

| 编号 | 要求与必要验证 |
| --- | --- |
| SR-AC-01 | 保留15秒自动静默更新；只有首次无缓存显示整表加载态。至少连续两个实际轮询期间列表不卸载、不闪空，成功自动应用新增/变化；请求失败保留旧行且提示可恢复，不能要求点击才接受正常新数据。 |
| SR-AC-02 | 搜索、国家/商店/分类、支持的排序、非首页及阅读位置进入详情后返回立即恢复，再后台更新；焦点回到合理的原入口且轮询不抢焦点。无缓存直接详情返回和缓存被淘汰有明确默认行为。 |
| SR-AC-03 | 完整queryKey和登录/演示上下文隔离，最多20查询缓存；切条件原子重置页码0。慢旧响应、取消后的响应及快速反复切换不能覆盖当前条件/结果，缓存不得把另一个查询结果标成当前结果。 |
| SR-AC-04 | 新行插入、行排序移动、内容高度变化时自动应用数据并维持可见appId相对阅读位置。锚点消失、结果变空或最后一页失效时按已定义回退，不跳到无效页、不循环刷新；行为在窄屏同样成立。 |
| SR-AC-05 | 隐藏标签停止新的定时刷新，恢复可见只补一次；定时、可见性、返回与手动触发不造成重复有效请求。退出列表/会话清理相应定时器和过期请求，详情及其他页面不被列表刷新无故重置。 |
| SR-AC-06 | CTO/前端实施者完成自检后，Alex独立验证连续轮询、详情往返、慢响应乱序、失败恢复、隐藏/恢复及桌面/窄屏主要流程；类型/构建和针对性检查通过。形成独立报告后由PM逐项验收，未验收不关闭#21。 |
