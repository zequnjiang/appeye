## 背景与范围

`com.creditouno.loan` 未进入阿根廷名单的已证原因是**此前来源没有返回该包**：Alex独立核对两轮AR三榜及三个关键词的已保存HTTP、SDK结果和队列，均未出现；该次每个词实际返回30条，没有保存可继续的token。实时AR详情可取得HTTP200，现有规则分析strong，因此本次不把问题描述成分类错误。原统一“250上限”提示不能解释实际覆盖，应改为展示真实请求参数和返回范围。

用户批准同时处理具体漏收与六国双商店扩展发现：泰国/th、墨西哥/mx、菲律宾/ph、巴基斯坦/pk、印尼/id、阿根廷/ar。保留产品内每60分钟应用发现/详情刷新；另增加独立、持久、每6小时调度的扩展发现通道，启用新国家后可沿配置参与。公开搜索、榜单、关联和开发者目录不能保证全商店枚举。

复用现有 `POST /api/apps` 按已知国家/商店/ID补录目标，并完成真实详情采集和当前规则分析。补录来源、请求接收时间与成功商店观测时间可追溯；接口返回或排队不能表示采集成功。重复补录沿用同一市场身份，不覆盖人工决定，不篡造当前商店发布日期。

## 来源与扩散

扩展来源包括轮转关键词、已有同国家/商店的开发者目录，以及有界的一层关联应用/开发者扩散。默认每市场一周期最多选择12个关键词、10个关联种子和10个开发者来源；使用持久last-served轮转，后续周期继续未处理来源，不总从名单头部开始。新结果经过详情与当前信贷规则后处理，扩散深度最多一层并保留父来源，避免循环无限展开。具体商店不支持的接口明确unsupported，不模拟成成功空结果。

Google Play使用当前指定SDK的搜索迭代能力，最多1,000个结果/查询。没有真实可恢复游标时，重启从查询头部重放、按身份去重并继续记录本次消耗，不能制造resume cursor或称已经完整结束。迭代中已返回的结果及时持久保存，预算/超时/中断不应丢弃已取得的原始结果。

App Store搜索请求使用 `num=200/page=1` 的公开窗口，不声明存在可继续的真实分页，也不保证每次返回200条；保存请求参数、实际返回条数及上游/SDK结束情况。HTTP/SDK异常沿有限失败路径处理，不能当成自然空结束。

## 持久调度与预算

扩展通道加入既有单writer协调器，共用限速、超时及采集锁。**每11个协调槽中保留1个扩展槽**，不是只有小时队列为空时才执行；空通道让出槽位。保留小时、原批次及手动工作原有执行机会，持续负载下各类工作都能推进。

每市场、每6小时周期使用以下可配置默认限制：

| 限制 | 默认值与口径 |
| --- | --- |
| 来源请求预算 | 60次真实HTTP，含SDK内部分页和重试，不把整个SDK方法只计1次。 |
| 候选详情预算 | 60次真实HTTP，独立于来源预算；默认不借用另一桶剩余额度。 |
| 单步时间 | 最多20秒；超时保留已获得结果、错误及未完成状态。 |
| Google单查询结果 | 最多1,000条；达到上限属于预算限制，不是全市场/搜索全集结束。 |
| 选择来源数 | 每市场最多12关键词、10关联种子、10开发者，并受上述真实HTTP总额约束。 |

来源任务与候选详情交替，市场、来源类型及种子/候选使用持久轮转，防止来源耗尽全部额度而候选永远无法详情验证。任务优先级、last-served与未处理frontier在重启后保持。每期预算耗尽以limited结束；未处理来源/候选显式deferred至下一期，不让旧active占位永久阻塞后续周期。重放从头的查询仍可能limited，不能假装完成；跨多个周期的测试必须证明老候选和其他来源获得执行机会。

所有网络发起走同一预算检查/记录路径，重试有界且计入对应桶。无需等旧#11全部评论结束才运行扩展发现。暂停国家不新增其自动任务，未开始自动任务跳过/延期，执行中的一次请求可以完成并保存来源；原全量批次仍采用自己的冻结参数。

## 数据、时间与诊断

所有已取得的来源结果、详情、分析、完整SDK原文及实际HTTP证据保留，记录国家/商店/ID、请求语言、关键词/种子/父来源、原观测时间、实际处理时间、周期、预算与停止原因。重启重放不重复应用同一持久响应；不同真实尝试保留独立证据。已缓存的历史开发者目录可回收为来源，但不能把本次处理时间改写成原网络获取时间。

新对象strong→自动confirmed、possible→candidate；insufficient保留完整暂存证据，不自动进入主库。已有主库继续刷新，人工/legacy优先。直接按已知ID补录是用户明确跟踪请求，其存在与自动发现准入分别表达；具体目标需完成真实strong分析，不能以空占位行代替修复。

新入库对象的firstSeen取同市场身份全部可信已保存来源中的最早时间。新增扩展来源必须纳入统一最早来源计算；原已有主库firstSeen不回写。回收旧目录、现在处理候选或分类发生变化都不等于今天商店新上架。市场动态的商店发布仍依据有来源的releasedAt，并保留日期精度及“不是该国首次可用证明”的说明。

新增小时或扩展发现对象分别归其周期；#11的2,024市场成员、原响应、快照、评论游标/seen及既有历史验收时间快照保持不变。合法更晚观测可以更新current，但不得回退更新的资料或改写旧成功时间。

页面支持按国家/商店/包名或App Store ID诊断：未发现、排队、暂存、失败、已入库，并明确预算延期、最近尝试、来源时间/路径、分析及停止原因。未发现仅表示系统尚无对应来源，不能声称商店不存在；自然结束、limited、deferred、失败和unsupported可区分。状态查询受认证保护且不隐式触发商店请求。来源窗口以实际参数/返回量说明，移除与实测不符的统一“250上限”。
