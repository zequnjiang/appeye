# 扫描统计查询索引优化：局部验收标准

- 关联：[完整采集 #11](https://github.com/zequnjiang/appeye/issues/11)。关联优化[缺陷 #17](https://github.com/zequnjiang/appeye/issues/17)；本项不另设采集总目标。
- 状态：PM需求交CTO隔离验证；尚未部署、未作性能改善或最终验收声明。文件仅定义本次索引优化范围，不改共同运营报告或真实任务。
- 已知测量：CTO于`2026-09-06T21:08:51Z`附近对真实库只读测得两轮summary约373/317ms；其中review added/updated聚合约292/159ms、结束原因分组约54/117ms、seen计数约16/26ms，其余查询约6–14ms。查询计划显示相关统计使用非覆盖索引读取含大response的任务表。这是两个有时间边界的样本；当时约74万评论、7,800页、数据库11.3GB，**不能据此认定全部采集变慢或网络等待都由本地统计造成**。

目的：让现有summary与只读状态查询更有效地读取所需统计字段。保留原统计SQL及其含义，通过必要索引改善访问计划；不增加缓存计数器、近似值或第二套统计真相。

| 编号 | 级别 | 可核对行为 |
| --- | --- | --- |
| SSI-01 统计完全等值 | P0 | 同一固定数据库状态下，索引前后使用原SQL，全部summary字段、类型、空值/零值、分组计数与added/updated累计值完全一致。覆盖多batch、多kind/status、空批次、result中字段缺失/零值及失败/排队不计入成功聚合等边界。不得修改SQL口径或用缓存/增量计数器替代现存记录。 |
| SSI-02 仅必要索引 | P0 | 实现仅新增必要索引DDL及其既有初始化/迁移接入，具有幂等保护；不改表中业务数据、分页/轮转/限速、summary调用节奏、分类、任务优先级或重排规则。只读`--status`等路径保持只读，不为了自动建索引打开写入或创建缺失库。 |
| SSI-03 隔离性能证据 | P0 | 在固定隔离数据上保存索引前后的相同统计结果、相关EXPLAIN QUERY PLAN和重复耗时样本，分别列summary总耗时及目标查询耗时；说明数据规模、索引构建耗时/大小和首轮/重复调用条件。目标查询确实采用预期更少读表的访问路径，并有可复现改善；若无改善则先解释或调整，不凭索引存在就通过。隔离基准不能称为真实生产速度提升。 |
| SSI-04 实际部署与单writer | P0 | 真实部署由CEO受控执行，继续单活动writer；如为索引构建暂停采集，记录原状态、停止/构建/恢复时间和运行版本，同batch按原检查点恢复。DDL失败必须保留错误并可重试，不跳过任务或恢复多个worker。读取真实进度时保持只读，不能在后台偷偷建索引。 |
| SSI-05 数据与恢复保持 | P0 | 隔离验证和实际部署前后保留旧task/attempt/response/HTTP、评论身份/raw/fetchedAt、seen及人工分类。新采集允许真实追加或更新，但必须由新响应解释；索引自身不造成旧数据变化、成功页重抓或游标丢失。建索引/重复启动不重复建同名索引，也不改变原重试预算或引入任务重排。 |
| SSI-06 真实性能表达 | P0 | 如实际部署，记录真实同SQL的计划与有时间戳耗时样本，说明当时数据规模、并发/暂停与缓存条件；将本地summary耗时、请求等待和整体页处理速度分别陈述。前后页数变化不能当作同一静态数据的等值证明；未控制网络等变量时不宣称整体采集加速比例或唯一瓶颈已解决。 |
| SSI-07 角色与验收 | P0 | CTO提交实现范围、自检及隔离基准，Alex独立验证结果等值、索引幂等/只读路径、查询计划和数据保持，PM独立审阅并在部署后核对实际证据。GitHub关联需求、自检、测试和PM结论；局部通过不关闭#11，也不替代评论全集与最终运行恢复验收。 |

生产处于持续采集时，统计前后可能自然增长。正确的等值比较采用同一冻结状态的隔离副本或同一受控停止点；不得把不同时间的增长误报为索引改变结果。性能测试使用真实只读摘要或明确标注的合成数据，公开报告不复制真实评论正文、作者或游标。
