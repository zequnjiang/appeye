## 目标

迁移到用户指定的两个维护分支，解决旧采集依赖维护问题；从多语应用资料识别信贷服务，解释识别依据并提取贷款条款和公司信息；已采集的完整响应保留并能在后台查看，补足发布者与权限资料。

指定来源为 [MrAdex77/google-play-scraper](https://github.com/MrAdex77/google-play-scraper) 和 [plahteenlahti/app-store-scraper](https://github.com/plahteenlahti/app-store-scraper)。可以使用它们实际发布的 npm 包或固定 commit，但锁文件和报告必须证明安装产物来自指定项目。不能只改 README 链接而继续使用旧上游包。

本轮保持 Node.js/SQLite 单主机架构、管理员认证、真实/演示隔离和既有国家配置；不要求增加外部 AI 服务密钥。识别结果是可解释的证据判断，不能变成牌照真实性、法律合规或商店准入承诺。

## 1. 识别与人工决定

自动分析输出 `strong`、`possible` 或 `insufficient`，保存分析版本、执行时间、源数据时间、命中原因及原文片段。文本输入包括可用的完整描述、摘要、标题及公司字段，不能只检查关键词。

| 级别 | 产品语义 | 最低行为要求 |
| --- | --- | --- |
| strong | 存在相互支持的信贷服务证据 | 至少有主动提供贷款、申请/发放贷款或撮合出借人的语境，再结合条款、金额、还款示例或具名主体等独立证据。 |
| possible | 有信贷相关线索，服务性质仍不确定 | 单纯 loan/credit 词、Finance 分类、一个公司名或无上下文百分比不足以确认。 |
| insufficient | 证据不足或主要是相反证据 | 无描述、普通钱包/记账/存款收益、仅计算器/指南且明确无贷款或撮合服务，不能自动确认。 |

需覆盖英语、泰语、西班牙语、印度尼西亚语、菲律宾常用 Tagalog 借贷词及乌尔都语样例。关键词是检索和识别线索，不是法律词表或完整语言理解保证。

否定与撮合必须分开处理：

- 仅用于计算分期、展示知识或比较产品、没有申请/撮合路径的工具不能因为出现 APR、期限和公司名就进入高置信。
- 明确“不直接放贷，但连接借款人与放贷机构”的应用仍可能是贷款撮合服务，不能以“不放贷”一句整体排除。
- 同时存在直接/撮合服务与计算器功能时，不能仅凭 calculator 一词否决。
- 存款 APY/理财收益率不能当作贷款 APR；本金、下载量和无单位数字不能当作利率或期限。

新建应用默认使用自动模式：只有 `strong` 自动成为 `confirmed`；`possible` 与 `insufficient` 保持 `candidate`，不自动排除。界面标注自动判断来源。人工设置 `confirmed`、`candidate` 或 `excluded` 后优先保存，后续采集和分析不得覆盖；用户可明确切回自动模式。

已有 v0.1 应用以兼容方式保留原分类，并按 legacy/manual override 处理，避免迁移后悄然改变已人工整理的应用库。重新分析可以更新建议和证据，但不能据此覆盖人工决定。

## 2. 披露抽取与政策适用性

官方来源及核对边界见 [政策来源](../policy-sources.md)，机器可读事实在 [policy-catalog.json](../../server/policy-catalog.json)。配置包含稳定规则 ID、本地研究版本、`retrievedAt`、来源链接及国家/商店适用范围。

字段约定：`minRepaymentTerm`、`maxRepaymentTerm`、`maximumApr`、`maximumInterestRate`、`fees`、`representativeExample`、`privacyPolicy`、`loanProvider`、`developerLegalEntity`、`corporateName`、`businessName`、`secRegistration`、`certificateOfAuthority`、`unregulatedStatement`、`ojkLicense`、`secpApproval`。

每个抽取结果至少保留原文片段、来源字段和规则/语义类别。数值可以附加规范值，但必须同时保留币种、周期和利率类型；无法可靠解析时保留文本，不捏造最大值或年化换算。

| 项目 | 展示和判断边界 |
| --- | --- |
| APR / 最高普通利率 | 两者独立；最高APR需要明确贷款成本及年化语境。CAT 等当地指标保留原名称，不无条件重命名为APR。 |
| 还款期 | 区分最短、最长、单位及分期/全额到期语境；不能把审核时长、促销期或分期日期当作贷款期限。 |
| 费用与示例 | 提取实际片段，零费用也是有意义的声明。仅找到“费用/示例”关键词不代表披露完整或算式正确。 |
| 主体/编号 | 保留具名主体及其角色、SEC/CA/OJK/SECP等声明；不验证其真实有效，不把监管机构名当作具体放贷公司。 |
| 条件项 | 泰国15%条件需明确适用利率及周期，信息不够时显示条件未判定；不从所有数字或任意百分比决定分支。 |

披露结果可以采用 `detected` / `not_detected` / `not_applicable` / `conditional` 或同等清晰状态。面向用户的含义必须是“已识别片段”“未识别”“不适用”“适用条件待判断”，不能显示“合规/违规/持牌已验证”作为机器结论。来源数据未取得时应说明未采集，不把它当成真实缺披露。

Google Play 专属规则只用于 Google Play。App Store 可共用一般信贷线索和事实抽取，但显示 Google Play 条款不适用；它们不是 Apple 审核规则。新增国家沿用适用的通用规则并说明当地法律未核验，不能静默继承另一个国家的阈值。

信贷研究范围宽于 Google Play 的个人贷定义。信用卡循环额度、房贷/车贷、EWA 与个人贷不同，需保留产品范围不确定性，不因属于“信贷”就把全部个人贷披露、期限限制标为适用。

## 3. 公司与发布者

后台应清楚区分以下事实，不自动合并为一个“公司”：

| 来源 | 角色 |
| --- | --- |
| 商店 developer / developerId / developerUrl 等 | 发布账号或开发者显示信息，可能是品牌，不保证是法律实体。 |
| App Store sellerName / seller 信息 | 商店披露的销售主体；与作者显示名分别保留。 |
| 商店额外 developer/legal/contact 字段 | 按上游原名和来源保存，不自动推断为放贷主体。 |
| 描述中的运营/开发法律实体/贷款服务方/合作机构 | 文本中的具名声明；每条保留角色和证据，不证明同一法人或牌照归属。 |

用户应能看到公司名称、可用 ID、地址、网站/联系方式及原始字段。来源没有返回时显示未提供，不能用应用标题、图标名或监管机构名填补。

## 4. 完整响应与权限

“全部信息保存并展示”在本轮指**已经成功采集到的响应字段全部保留**，不限于当前规范化白名单。详情中同时提供便于阅读的常用字段和可展开的完整原始数据。未来上游新加字段不应因本地映射未更新就被丢弃。

至少覆盖应用详情、所执行的搜索结果、评论、发布者/开发者补充信息以及权限补充采集的成功响应；没有执行的商店接口不假装已覆盖，不以无限抓取全部评论/关联应用为验收要求。

Google Play 尝试调用维护分支可用的权限能力；保留返回组、名称、标识、描述及未知字段。App Store 未提供同类 Android 权限时应标注不支持或未提供，不能显示“无权限”。商店隐私标签、Android 权限列表、APK Manifest 和运行时访问不是同一种证据。

补充采集具有独立的 `not_collected`、`ok`、`unsupported`、`error` 或等效状态，并保存采集时间、来源和错误。成功空数组与未采集/失败明确区分。详情成功而权限失败时仍保存详情，权限失败有记录，不能让全部任务静默成功或覆盖上次成功的权限资料。

完整原始数据和补充信息需要持久化，可通过详情/API查询；页面分页、折叠可以控制体积，但不能只展示截断数据而没有继续读取完整内容的入口。无需下载/反编译 APK，权限来源限制须在界面可理解。
