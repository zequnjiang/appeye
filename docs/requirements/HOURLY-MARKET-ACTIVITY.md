## 目标与采集范围

系统持续按每 60 分钟的周期安排应用发现与详情刷新。用户在现有独立「市场动态」页面查看各国当天首次发现、商店披露的发布日期，以及实际观测到的版本、更新说明和其他字段变化；可进入应用详情追溯来源。

周期监测覆盖启用国家配置下已进入主应用库的记录，包含 `confirmed`、`candidate` 与人工 `excluded`，刷新不改变人工分类。国家配置的关键词用于双商店发现，新国家启用后无需改代码即参与周期调度。发现范围保持当前公开接口及关键词可取得的范围，不能命名为全市场枚举；新结果遵循现有 Finance 发现的入库筛选：`strong` 自动以 confirmed 进入主库，`possible` 以 candidate 进入主库，`insufficient` 不新建主库应用，完整来源、详情和分析保留在本周期账本。已有主库应用即使本次 insufficient 仍刷新保留；人工优先及原始数据口径继续遵循 V0.2。

每小时安排的是发现和应用详情请求，覆盖详情中实际返回的版本、更新说明、描述、评分、商店时间、发布者及其他原始字段。七类补充资料及历史评论不因每个小时到来而全部重新抓取；其原有采集策略和当前全量批次继续执行。小时设置不能覆盖或重置当前批次的冻结参数、游标、响应和历史。

当前 #11 的主库补齐范围已冻结为 2,024 个市场记录，后续小时发现的新应用分别归入小时周期记录，不自动扩张旧批次分母或制造永远无法完成的批次。#11 最终验收依据其冻结成员及对应快照、响应、seen 和历史；更新更晚的当前快照或当前资料是合法的新观测，不能仅因与旧时间快照不同就判为数据损坏。原快照、原始响应与人工/legacy 分类仍须保留，旧报告中的历史时点不得回写成最新状态。

“每小时”指持久调度周期，不承诺所有国家、所有应用在同一时刻获得新资料。实际完成受请求限速、上游耗时和应用数量影响；页面必须显示最新成功观测时间及排队/延迟状态。不能把已排队、沿用旧数据或采集失败表示为本小时更新成功。

## 事件与日期口径

| 视图 | 入选依据 | 必须说明 |
| --- | --- | --- |
| 新发现 | 本系统 `firstSeenAt` 落在所选自然日 | 是系统首次发现，不等于商店新上架；重新采集和重启不改首次发现。 |
| 商店发布 | 有来源的商店 `releasedAt` 落在所选自然日 | 显示商店披露日期、实际观测时间及来源。只证明该日期字段，不证明该国首次可用或完整市场上架名单。缺失时不纳入。 |
| 应用更新 / 变化 | 成功快照间实际变化的 `observedAt` 落在所选自然日 | 显示观测时间、商店更新时间、版本变化及字段前后值。不能按 `storeUpdatedAt` 代替系统观察日，不能把评分变化算版本发布。 |

默认日期为 `Asia/Shanghai` 下的今天，页面显式显示所用时区和日期。日期过滤使用该时区的当天 00:00（含）至次日 00:00（不含）；后台储存仍使用带时区的时间。API 返回实际 `date`、`timeZone` 与起止边界，前端不得悄然换成浏览器时区。首版可以固定这个时区并只提供日期选择；若支持其他 IANA 时区，需校验并按真实日界处理。

商店仅返回日期而无时区时，应保留来源精度和原值，不能制造精确发布时间。首次获得该记录时已有的历史发布日期可以出现在所选发布日，但首次快照不产生一次“版本更新”。空值变为已知值、已知值变为空值可以作为资料可见性变化展示，不能据此认定发布新版本；沿用有效版本连续观测规则。

只有日期的 `releasedAt` 按商店原日历日期匹配所选日期，不能擅自补上 UTC 午夜后造成跨日；带时间和时区的值按所选时区的时间边界匹配。两种精度在事件中可区分。

一个应用同日可以同时属于多个视图。各视图的应用数按 `(country, store, externalId)` 去重，展示多次变化时分别保留事件时间；同一应用在两个国家是两个市场记录。汇总说明应用数与变化事件数不同，过滤后的计数与列表范围一致。

新对象此前若已在旧全量批次或旧小时周期中暂存为 insufficient，后来才成为 strong/possible 进入主库，其 `firstSeenAt` 取相同国家/商店/ID在全部已保存可信来源中的最早观测时间。首次进入主库、首次成为信贷候选与本系统首次发现不同，不能用新分类或本次入库时间改写真实发现日。没有过去来源时才取本次真实首次观测；本次澄清只适用于新入库对象，不回写既有主库的 firstSeenAt / legacy 记录。

## 调度与 API 契约

通过产品内 Node.js scheduler 和现有持久化基础设施实现，不使用外部 Codex automation。持久记录下一次应调度时间或等效周期标记；首次启用可立即安排一次。现有国家配置的小时监测设置应迁移/设为 1 小时，并保留国家启停、关键词、语言及既有数据；界面与实际周期一致，不能配置仍显示 24 小时而后台按 1 小时执行。

每个国家/商店/关键词的发现、每个应用的详情刷新，在同类任务已经排队或执行时进行合并或跳过重复入队。停机多个周期后恢复最新一次应执行工作，不逐小时补出无界积压；失败保留有限重试，后续周期仍可再尝试。暂停国家后不再创建其周期任务；已经排队但尚未开始的自动监测任务应跳过/暂停，执行中的单次请求可正常结束，历史保留。当前全量批次沿用自己的冻结国家范围。

小时监测和全量批次必须共享明确的互斥执行/协调机制；不能新开无协调 worker 与批次争抢、覆盖同一任务或产生并发写竞争。两类工作使用有界配额或时间片交替，报告实际实现的公平边界；既不能将每小时任务压到全量评论全部完成以后，也不能让全量批次在监测持续到达时永久停滞。两边共同遵守原商店限速和单 writer 原则。

API 路径由 CTO 选择，最少支持事件类型、日期、国家、商店、分类、分页条件；响应提供实际时间边界、过滤后的计数和分页信息。事件数据包含应用身份/链接、当前分类、事件类型、来源时间与观测时间、实际变化字段及前后值，能追溯已有快照或变化记录。筛选分类按查询时当前分类，明确不是事件发生当时的历史分类。接口参数无效时返回明确错误；API 与页面均受既有认证保护。

## 验收标准

以下均为 P0。实现选择可以不同，但每项必须以确定性测试、实际部署/浏览器证据或明确范围验证，不能仅以代码存在作通过依据。

| 编号 | 验收要求 |
| --- | --- |
| HMA-AC-01 | 产品内持续按 60 分钟安排双商店发现及主库详情刷新；配置/UI 与实际周期一致。六国及新启用国家参与，人工分类（包括 excluded）保留。测试明确首次启用、未到期、到期三个时点。 |
| HMA-AC-02 | 调度进度、任务和去重状态持久化；重启后继续，重复 tick/启动不重复同一待执行工作；停机跨多个小时只恢复最新应执行工作，不逐周期堆积。 |
| HMA-AC-03 | 国家暂停后不新增自动周期任务，未开始的自动任务不继续采集；恢复/新增国家可按小时参与，语言、关键词及人工设置保持。当前全量批次的冻结配置不被改写。 |
| HMA-AC-04 | 有限重试、上游限速和失败可追溯；失败不覆盖最后成功资料，不生成虚假变化或改 firstSeenAt。连续失败后的下一周期可再次尝试，不形成永久占位或无限即时重试。 |
| HMA-AC-05 | 小时任务与全量批次有单 writer 协调、并行进程互斥和可验证的公平执行边界。合成队列证明两类任务均持续推进；真实受控部署证明旧游标/响应/历史保留并恢复，监测不必等待全部历史评论结束。 |
| HMA-AC-06 | 每小时不重新排入全库七类补充和全部历史评论；既有补充/评论记录与执行策略保留，当前 #11 仍能继续分页。其 2,024 个市场记录范围冻结，新小时发现另归周期；旧响应/快照保留，合法后续观测不冒充旧批次获取时间。小时任务总量、合并/延迟状态可追溯。 |
| HMA-AC-07 | 现有独立「市场动态」页面升级为可切换的新发现、商店发布、应用更新/变化视图，有日期、国家、商店、分类筛选以及分页/继续读取。空态、错误态、加载状态可理解，应用可进入详情。 |
| HMA-AC-08 | 新发现严格按 firstSeenAt；商店发布严格依有来源 releasedAt，缺失不冒充。历史发布但今天才发现、今天发布并发现、仅首次快照、重复采集、过去暂存insufficient后续才入主库均正确；后者取历史来源最早真实发现日，既有主库时间不回写。页面说明发布日期不等于所选国家首次上架证据。 |
| HMA-AC-09 | 变化按 observedAt 归日；真实版本变化、更新说明、描述及其他支持字段提供前后值/完整内容入口，并分别显示 storeUpdatedAt。相同快照、失败和首次快照不制造更新；空版本恢复不假算新版本。 |
| HMA-AC-10 | 默认 Asia/Shanghai 的“今天”与明确展示一致，API 与页面共用日界；UTC 跨日、当天 00:00、次日 00:00及非法日期有测试。未支持的时区不被静默误用。 |
| HMA-AC-11 | 应用身份、去重、分页与过滤计数一致；同日多次变化可追溯，当前分类筛选和双国家同应用不混淆。中断重放不重复产生同一变化，旧历史资料不被改写为今天发生。 |
| HMA-AC-12 | 页面显示实际最新成功观测时间、调度周期和排队/逾期/失败状态或可直达相应任务，不把调度触发当更新完成。源字段缺失使用缺失说明，GP累计安装和Apple下载缺失口径保持。 |
| HMA-AC-13 | 未登录的数据接口被拒绝，合法登录可使用新页面；演示标识与真实数据隔离保持，长描述/原始内容以安全文本展示。受影响桌面和窄屏主要流程有浏览器验证。 |
| HMA-AC-14 | CTO 自检、Alex 独立回归、PM 逐项验收和受控运行证据关联 #18；类型检查/构建及相关测试通过。真实采集与模拟时钟/夹具分开报告；#11 的未完成评论或源错误不被本需求的通过结论掩盖。 |
