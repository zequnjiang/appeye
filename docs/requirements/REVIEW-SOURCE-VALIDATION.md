# 评论来源响应校验：局部修复验收标准

- 关联：[缺陷 #16](https://github.com/zequnjiang/appeye/issues/16)、[完整采集 #11](https://github.com/zequnjiang/appeye/issues/11)、[原运营范围](FULL-SCAN-2026-09-07.md)。本项不新增后台界面、来源或采集总目标。
- 状态：CTO自检、Alex独立12专项/132完整检查与runtime-6真实部署核验、PM独立只读验收均通过；见[PM局部验收](../reports/REVIEW-SOURCE-VALIDATION-PM.md)。代码522d86e，CEO发布报告并确认最终CI后可关闭#16；真实评论全集与#11仍未完成。
- 已知事实：CTO静态审查确认两条可误判路径：GP评论RPC `UsvDTd`的null payload与非零错误可被SDK映射成空数组/无游标；Apple评论解析仅提取`entry/im:rating`时，HTTP200的错误HTML或坏XML可能被映射为空。CTO此前对真实GP649页（含30个空页）只读检查未发现该结构化错误；随后已存证的新事务为901页/49空/0明确错误。Alex另独立核725个成功Apple页，524非空、201合法空、18,024条XML字段投影一致。这些是有时间边界的排查结果，**目前没有本轮真实误判或数据损失证据**，不把静态缺陷写成已发生事故。

修复目的：只有已核对的合法来源空响应才参与自然结束判断。真实上游错误进入原有有限重试和可恢复失败流程，已取得评论和原始HTTP继续保留。

| 编号 | 级别 | 可核对行为 |
| --- | --- | --- |
| RSV-01 原始HTTP | P0 | 校验前按原传输记录保存实际HTTP状态、完整原body、真实获取时间及batch/task关联。校验只能读取或克隆响应，不覆盖原文、不制造替代空feed；HTTP200也可能是业务错误。保存失败和校验失败须可区分。 |
| RSV-02 GP明确错误 | P0 | 仅在当前GP评论请求及对应`UsvDTd`响应语境识别已证错误结构。明确非零RPC错误不能作为`[]/no token`返回成功，须给出可定位的校验错误。不能仅因payload为null、评论数组为空或没有token就拒绝合法空响应；不将其他RPC或无关片段的错误归给本页。 |
| RSV-03 Apple合法feed | P0 | 校验实际评论响应为可正常解析的预期XML feed。合法有评论feed、无评论feed及仅有正常feed元数据/应用元数据的合法空feed均通过；HTTP200错误HTML、错误文档、破损XML或缺少预期feed结构必须失败，不能仅因提取不到`im:rating`就宣称自然空页。验证依照已安装库与真实响应结构，不引入未经核实的必填字段或新的远程请求。 |
| RSV-04 分页状态 | P0 | 来源校验失败不写成成功空页，不设置自然结束、无游标结束或接口上限完成；失败页保留原请求页码/游标和国家/语言。合法GP空页仍有新token时继续，真实无next才沿原规则结束；Apple合法空feed及公开页边界沿原规则，其他分页与轮转行为不改变。 |
| RSV-05 有限重试与历史 | P0 | 复用原有限预算、退避和中断恢复。校验失败产生真实失败attempt与可追溯HTTP错误证据，不无限重置预算；此前成功页、评论raw/身份/获取时间、seen与检查点保持，不删除评论或伪造新观测。成功重试只计实际新增/更新，已保存成功页不无故重抓。 |
| RSV-06 范围控制 | P0 | 不改变六国双店、2,024条市场记录、全部可分页评论义务、限速或补充阶段已验收结果；不批量重排全部成功页。若实际历史响应审计发现受影响页，应先明确batch/task/原HTTP和恢复原因，再交CEO安排有界恢复；未发现则明确无已证历史修复对象。 |
| RSV-07 独立回归 | P0 | CTO自检后交Alex。确定性测试覆盖GP明确错误与合法空、合法空+新token、非目标RPC隔离；Apple有评论/合法空/元数据空、错误HTML/错误文档/坏XML/错误根结构；provider→HTTP留存→runner失败重试→成功恢复的联动，以及预算耗尽不假自然结束、旧评论与原时间保持。真实数据只读核查与fixture结果分别报告。 |
| RSV-08 验收证据 | P0 | 提交实现/自检、Alex正式报告、实际运行代码标识和PM结论，关联#16。部署后核对实际新增页仍可处理、没有误伤合法空页；已保存真实历史范围的检查须给时间、分母与异常数，不能用抽样冒称全集。缺陷修复通过不等于评论全集或#11整体完成。 |

CTO可选择最小的本地响应校验实现，继续使用现有两家维护库和传输账本；无需更换依赖、修改上游包或改变产品分类。错误状态保留具体原因，不提前将结构/解析错误验收为外部来源限制。最终是否需要历史恢复以实际响应证据为准。
